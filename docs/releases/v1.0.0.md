## Overview

NetDoctor is a free, open-source Windows desktop application that helps users investigate network connectivity problems through evidence-based diagnostics, understandable explanations, and practical troubleshooting recommendations.

Version 1.0.0 introduces a unified guided troubleshooting experience, bringing together NetDoctor's diagnostic capabilities in an interface designed for everyday users.

The application focuses on identifying what network measurements establish, what they suggest, and what remains uncertain.

---

## What's New in v1.0.0

### 1. Guided Network Troubleshooting

The Ask NetDoctor interface provides seven guided questions:

1. **What's wrong with my internet?**
2. **Why is my port forwarding not working?**
3. **Why is my internet slow?**
4. **Why does my internet keep disconnecting?**
5. **Why won't a website open?**
6. **Which VPS location has the lowest latency?**
7. **Is my VPN working?**

Each workflow provides relevant checks, explanations, and recommended next steps.

### 2. Internet Fault Isolation

The main internet diagnosis combines available evidence from:

- Windows network adapters
- Default routes and gateways
- Gateway responsiveness
- DNS queries
- External HTTPS connectivity checks

Optional user-reported comparisons involving another device or network can help narrow the possible fault.

NetDoctor does not claim that one computer can definitively identify every router or ISP problem.

### 3. Port Forwarding and CGNAT Guidance

NetDoctor recognizes private IPv4 and carrier-shared address ranges.

It provides guidance for potential upstream NAT limitations, including:

- Checking upstream routers
- Contacting the ISP about public IPv4 availability
- Using authorized private overlay networks
- Investigating compatible public tunnels and relays

The application does not automatically modify router settings or verify inbound port reachability.

### 4. Unified Application Navigation

The desktop interface includes:

- Ask NetDoctor
- Overview
- Diagnosis
- Activities
- Stability
- Cloud Regions
- Network Details

A persistent sidebar provides access to the available tools.

### 5. Navigation Protection

Foreground diagnostic operations now restrict navigation while a check is in progress.

This prevents users from accidentally leaving workflows that cannot safely preserve their active state.

Navigation automatically becomes available after the operation completes.

Background-capable operations, including the Overview speed test and stability monitoring, retain their intended navigation behavior.

### 6. In-Page Permission Dialogs

Browser-native confirmation windows have been replaced with NetDoctor-styled permission dialogs.

Users must approve relevant external tests before they begin.

Canceling a confirmation prevents the associated operation from starting.

### 7. VPN Exit-IP Comparison

NetDoctor can compare public-IP information before and after a VPN connection is established.

Results may identify:

- Changes in observed public IP
- Changes in IP-based country
- Changes in the observed exit network

This is not a complete VPN encryption or leak-security assessment.

NetDoctor v1.0.0 includes:

- Latency and jitter observations

- DNS and HTTPS connectivity checks
- Website-specific diagnostics
- Connection stability monitoring

## Privacy

NetDoctor operates locally without requiring an account or subscription.

- Diagnostic history is stored locally.
- External measurements require user initiation and consent.
- External destinations may observe the user's public exit IP.
- No paid cloud account or infrastructure is required.
- NetDoctor does not automatically modify Windows networking or router settings.

Saved application data and diagnostic logs may remain after uninstalling.

---

## Known Limitations

NetDoctor is a diagnostic aid, not a replacement for professional network analysis.

- A single-PC test cannot establish every root cause.
- Short tests may miss intermittent faults.
- Failed ICMP probes do not necessarily indicate a failed router.
- Direct DNS results may differ from browser behavior.
- Successful TCP connections do not guarantee throughput.
- Cloud-region endpoint timings are not actual VPS benchmarks.
- VPN exit-IP comparisons are not comprehensive security audits.
- Private WAN addresses alone do not establish ISP-level CGNAT.
- External service policies and availability can affect test results.

NetDoctor distinguishes observed measurements from possible explanations and unresolved causes.
